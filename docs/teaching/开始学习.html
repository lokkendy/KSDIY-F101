课程 01

认识板子

从点亮屏幕到独立开发应用。课程以 KSDIY F101S3 4.3 英寸开发板为例，全程记录芯片、屏幕、镜像版本和验证结果。

项目 教学基线
处理器与存储 F101S3，16 MB PSRAM，16 MB SPI NOR
显示与触控 ST7102 MIPI 480×800，ST7123。横屏逻辑分辨率 800×480
调试与无线 UART4，PD6 TX、PD7 RX，115200 8N1。选配 AIC8800D40L
电源与音频 参考板使用 AXP2101，短按 PWRON 可息屏／唤醒。供电和音频端口看随板标注

准备数据线、Windows 电脑、随板说明、对应 IMG 和烧录工具。串口为可选项。连接串口前确认板上电平和端子定义，共地并交叉连接 TX/RX。上电和 FEL 操作以随板的板卡图为准。

学习顺序 完成后能展示
01–03 · 入门 上电、烧录、记录日志，修改一处 UI 后打包
04–05 · 项目 选一个本地或无线应用，写出输入、状态和验收项
06–09 · 进阶 排查 Wi‑Fi/TLS，定位图传瓶颈，让 AI 协助复现和修复

F101S4 的 32 MB PSRAM、供电与初始化需要独立验证。7 英寸和 10.1 英寸屏也要分别校验屏参、触摸坐标、刷新与缓冲开销。这些规格尚未列入本教学基线。

课程 02

首次点亮与恢复

先确认 USB 设备在哪个阶段

阶段 去哪里看 能证明什么
FEL OpenixSuit 设备列表 Boot ROM 正在等待装载，可用于写入适配 IMG
RTOS 正常启动 屏幕、启动串口、适用应用的 ADB 已进入应用，可继续检查触摸、网络和日志
USB 副屏运行中 副屏 USB 接口和发送端 镜像使用自己的 USB 功能，调试用串口

操作卡

  1. 写下板号、芯片、屏型号、Flash 类型与镜像版本。如果板已预烧录，先正常上电确认启动、触摸和亮度，记下出厂基线。可先做「实验／读启动日志」。
  2. 取得随板镜像及 SHA-256，运行附带校验脚本。使用随板工具版本，按板卡说明进入 FEL，确认设备就绪，再选择对应 IMG。
  3. 首次安装使用该镜像说明指定的模式。跨应用切换前考虑备份。已有配网、登录资料时，先检查升级包分区清单及 UDISK 是否会写入，再选择保留数据升级。
  4. 等工具确认完成后正常重新上电。记录开机版本、分辨率、触摸是否于四角正常。使用 ADB 的应用可运行：
adb devices -l
adb shell logcat

logcat 仅适用于提供该命令的镜像。遇到空列表，先区分数据线、FEL 残留、USB 功能差异和应用启动状态。串口日志可作为旁路。停在 DRAM 初始化时先复核镜像、硬件和启动参数。写入失败时记录最后成功阶段，再用同板型已验收镜像恢复。

课程 03

编译第一个应用

先跑通原版

使用 WSL2 的 Ubuntu 24.04 或发布方指定的已验证环境。将 SDK 解压到 Linux 文件系统，例如 ~/f101/sdk。SDK 依赖大小写文件名、软链接、玄铁交叉工具链和可执行的 32 位 x86 打包工具。在取得匹配的 SDK、获准使用的 KSDIY 项目和随版依赖说明后，运行：

cd ~/f101/sdk
test -L envsetup.sh
test -f lichee/rtos/projects/f101s3/ksdiy_f101s3/tools/build_all_apps.py
source envsetup.sh
lunch_rtos f101s3_ksdiy_f101s3
python3 "教学包实际路径/工具/编译木鱼.py" \
  --sdk ~/f101/sdk \
  --config "教学包实际路径/工具/wooden_fish.defconfig" \
  --out "$HOME/f101-out/wooden-fish-base"

把「教学包实际路径」换成解压后的 Linux 路径。--out 必须指向新目录。教学包附木鱼配置，仍需要随板提供的匹配 SDK 快照。脚本完成后检查 manifest.json、IMG 和 SHA-256。失败时先看 wooden_fish.build.log 或 wooden_fish.pack.log。当前开发树用通用批量脚本全清后出现过 SDMMC 重复定义，入门时使用匹配的发布基线与上面的单应用构建流程。

第一处修改

从工程根目录打开 src/app/apps/wooden_fish/Pages/Fish/Fish.c，在 ui_create_page_header 找到页面副标题，换成自己的短句。需要双语时一并补 src/app/Model/app_i18n.c 词条。用不同的 --out 再打包，确认新哈希与旧包不同，上板检查新文案、触摸敲击与计数。

附带的按键计数实验可先在电脑上完成。请保留原版 IMG 作为恢复版本。

课程 04

从例程到新应用

沿着一次触摸找到代码

层 从哪里看 练习
应用入口 App_f101.c、app_shell_cfg.c 找到启动路径与页面注册
页面事件 apps/wooden_fish/Pages/Fish/Fish.c 找到触摸如何变成敲击，界面如何更新
状态与保存 apps/wooden_fish/Model/、Model/settings.c 标出显示状态和持久化各自的所有者
硬件与配置 HAL/、工程 defconfig、board/f101s3/ksdiy_f101s3/configs/ 找脚位、驱动开关和打包配置
跨线程 Common/ui_dispatch.c、Model/data_bridge.c 将后台结果交回 UI 线程渲染

应用文件位于工程的 src/app/。board/ 是 SDK 根目录下的板级配置。

小项目 · 桌面计数器

用附送的 C 实验处理按住只计一次、释放再按、清零与计数上限。随后在现有例程上加计数显示和清零按钮。把网络调用、文件写入和长运算移到应用工作任务，UI 线程负责显示状态与处理用户输入。

验收时提交上电、一次长按、连续三次独立点击、清零四组记录。选做保存时增加完整断电后的回读证据。写入失败时应能继续使用本轮内存状态，并明确提示。

画板与泡泡纸适合练触摸与局部刷新。时钟与老黄历适合练定时更新。钢琴与木鱼适合练音频队列。保留窄屏和横屏的验收，检查长中文和百分号在边缘是否被裁掉。

案例 可学习的内容 验证边界
木鱼、画板、时钟、钢琴等 LVGL、触摸、定时、音频和持久化 有批量构建记录。SKU 实测按索引
TF 卡 MP4 播放器 本地文件、硬解、旋转、HP/PA 音频 S3 有独立镜像。S4 降频恢复曾出画出声，60 fps 同步未验收

用与手头设备匹配的版本演示。需要授权的案例使用自己的账号和设备，演示视频和课件使用脱敏日志。

课程 06

联网、账号与保存

逐层排查 Wi‑Fi

从一个已经正常启动的镜像开始，依次记录 SDIO 初始化、驱动就绪、扫描、关联、DHCP、对时、TLS、业务登录。每层留下一个标志日志或错误码。连上热点但没 IP 时先检查 DHCP。TLS 因时钟失败时，先核对对时与 DNS，再定位认证。

完整断电验证保存

  1. 使用自己的测试网络和授权账号，完成首次连接或登录。
  2. 确认文件系统已挂载且保存成功，只记录存在性和校验结论。
  3. 断开屏幕板供电和 USB，重新上电，观察自动联网、会话恢复和设备列表。
  4. 单独测试升级保持。对照新旧分区地址与大小、镜像实际下载分区表，再记录升级前后的保留结果。一次冷启动通过只证明该次保存和加载生效。
现象 核对方式
公网有状态，首页显示离线 分开定义 Wi‑Fi、云会话、打印机状态，检查当前选中设备的 ID
相机或存储没有数据 检查云端列表是否完成，是否匹配到同一台设备的局域网地址与认证
设备已执行，按钮还显示旧状态 分清下发、应答和回读。超时保留最后确认的值并给出提示

拓竹案例可用只读状态、相机和文件列表完成。公网控制权限、局域网开发者模式与打印机型号分别验收。

课程 07

视频案例 · 从收到帧到真的出画

网络分片经过完整访问单元、硬解帧、G2D 转换、LVGL 绘制，最终翻页。每个阶段都有自己的计数。采样注明镜像、分辨率、方向和场景。

症状 第一组对照
纯绿屏 对同一解码帧做 CPU 与 G2D 对照，核对 NV12、stride、裁剪、DMA 地址、缓存和色彩范围
运动时花屏 查丢片、乱序和重复包，受损参考链等待关键帧恢复
整屏闪 暂停更新对照，核对帧所有权与转换完成时机，再比较翻页方式
延迟增大 同时看压缩队列、解码帧池和 UI 积压，UI 跟不上时优先跳过展示
切换或重连异常 等接收、解码与显示消费者完成后再释放共享缓冲

Action 6 R16 的 60.19 秒横屏样本中，解码约 29.97 fps，绘制约 21.75 fps，完成翻页约 21.73 fps。三轮重连后的 30.08 秒样本完成翻页约 22.08 fps。曾出现一次视频停止、控制仍在线，根因未定。数据只代表当时的镜像和测试条件。

打开「实验/图传帧率」，用只读分析器复算实测样本。复制样本后把其中一个累计计数改为回退，观察工具如何排除无效区间。作业交出解码、绘制、完成翻页三个指标，说明哪一个回答「屏幕实际有多快」。

课程 08

用 AI 和资料包一起开发

把「AI协作/F101项目上下文.md」、任务模板、相关课程和工程的少量相关源码放进 AI 工作区。指出真实 SDK 根目录，并说明 AI 能否读取。使用稳定版本创建可回滚的工作副本。

  1. 先定位。 提供板型、固件哈希、操作顺序和覆盖失败点的脱敏日志。让 AI 标出代码位置和证据。
  2. 一次解决一个问题。 指定验收门槛。优先复用现有 API，从可回滚的小改动开始。运行烧录命令前核对目标板、分区和恢复包。
  3. 分开跑验证。 先主机、再编译打包、再上板。让 AI 保留命令、SHA-256、实机数据和待测项。
  4. 记录失败。 当帧率没改善时，先确认测的是收到、解码、绘制还是翻页。保留成功与失败样本和回退办法。

可以直接复制的任务

这块板是 F101S3 / 4.3 英寸触摸屏。用资料包找到木鱼页面的触摸入口。先列出页面、模型和保存路径，再增加清零按钮。清零后界面应立即更新。先跑主机验证，输出变更文件和单应用构建命令。保留旧 IMG 供回退。

另一个练习是给 Wi‑Fi 页面增加「等待获取 IP」和「正在校时」两种反馈。用日志说明目前卡在哪一层。Wi‑Fi 密码、二维码令牌、访问码和 /data 完整备份保存在本机私有目录。

开发过程与验收

阶段 已解决或验证的内容 对应学习点

每次交作业都写这六项

板型与屏幕、镜像与哈希、修改点、操作步骤、量化结果、待验证项。用真实设备反馈和板端日志交叉确认，并标出主机、板端和用户确认三种证据来源。

新增 SKU 时，用同一张表覆盖首次烧录、四角触摸、横竖屏、冷启动、配网、音量和恢复。跨屏尺寸记录实际耗时与内存。产品例程按实测边界展示，教学案例保留可复盘的已知故障。
